# Доклад (до 5 минут): спикерские заметки

Цель: показать комплексную архитектуру и практические сценарии умного стадиона, интеграции с MAX и ЕПГУ, а также подход к безопасности.

## Тайминг (≈ 5 минут)
- 0:00–0:30 — Вступление и выбор домена
- 0:30–1:30 — 5-уровневая архитектура (обзор)
- 1:30–3:00 — 5 ключевых сценариев
- 3:00–4:00 — Принцип работы и протоколы
- 4:00–4:30 — UI и ценность для ролей
- 4:30–5:00 — Безопасность, отчётность, Q&A

## Вступление (0:30)
- Мы рассматриваем не ЖК/квартиру/город, а умный многофункциональный стадион: динамичные потоки, массовые мероприятия, смена режимов.
- Внешние интеграции: MAX — коммуникации с посетителями; ЕПГУ — верификация ID/возрастных ограничений; GR — энергетика и надзор.

## Архитектура (1:00)
- Уровень 1 — устройства: турникеты, биометрия, камеры, датчики CO₂/вибрации/погоды, HVAC, ЭЗС, RTLS.
- Уровень 2 — подсистемы: СКУД/периметр, ОПС/СОУЭ, VMS+AI, навигация, ритейл, парковка, энергосбережение.
- Уровень 3 — BMS/АСУЗ²: интеграция BACnet/Modbus/OPC/ONVIF/OCPP, сценарии «Матч/Концерт/Ночь/Эвакуация», цифровой двойник.
- Уровень 4 — Платформа+клиенты: микросервисы, шина, хранилища; Mobile для посетителя, Web/desktop для диспетчера/организатора.
- Уровень 5 — Внешние: MAX, ЕПГУ, GR, платежи, страховые/медицинские.

## Сценарии (1:30)
1) Вход: e-ticket через MAX/Mobile, биометрия (по согласию), валидация и контроль дублей; камеры фиксируют проход.
2) Анти-скопления: видеоаналитика → пересчёт маршрутов, пуши в зонах, переключение табло и голосовых объявлений.
3) Еда к месту: заказ из Mobile, POS+CEP оптимизируют очередь/окно, ETA и выдача по QR.
4) Эвакуация: триггер ОПС/AI → сценарий, разблокировка путей, маршруты в Mobile/MAX, контроль диспетчером.
5) Энергия: предпрогрев/предикция пиков, сбор АСКУЭ, отчёты в GR.

## Принцип работы и протоколы (1:00)
- Полевые протоколы: BACnet/Modbus/KNX/DALI/DMX для инженерии и сцены; IoT на MQTT/LwM2M для датчиков; ONVIF/RTSP для видео; OCPP для зарядок.
- Событийная архитектура: Kafka/NATS + CEP для правил; time-series + объектное хранилище; API Gateway и RBAC/ABAC.
- Безопасный транспорт: TLS 1.3/mTLS, JWS для команд; OIDC/OAuth2.1 для пользователей и интеграций.

## UI и ценность (0:30)
- Mobile: быстрый вход (QR/NFC/биометрия), навигация с учётом скоплений, еда к месту, SOS.
- Web: карта со слоями, сценарии и отчёты, роли и права для разных участников.
- Вайрфреймы: `docs/ui/*.svg` (5 экранов), состояния/ошибки/доступность — в `docs/ui.md`.

## Безопасность и отчётность (0:30)
- Сегментация IT/OT, обновления, RBAC+MFA, подписанные команды, защита интеграций MAX/ЕПГУ, KMS и ротация секретов.
- Отчёты: GR (энергия/инциденты), SLA арендаторов, а также аудит действий операторов.

## Ожидаемые вопросы и ответы (Q&A)
- В: Что делаем при отказе MAX или отсутствии сети у пользователя?
  О: Фолбэк — оффлайн-токен QR и ручные стойки помощи; каналы оповещения дублируются (табло/голос/SMS при необходимости).
- В: Как соблюдается приватность при биометрии?
  О: Опция только по согласию, шифрование, локальная/псевдонимная идентификация, сроки хранения, аудит доступов.
- В: Как масштабируемся на концерт с другим профилем потоков?
  О: Переключение сценариев (Концерт), иные профили HVAC/света/навигации; SLA для арендаторов.
- В: Что при DDoS на публичные API?
  О: WAF/Rate limiting, очереди, Circuit Breakers; критичные контуры эвакуации изолированы.
- В: Как верифицируем возрастные ограничения?
  О: Через ЕПГУ по согласию пользователя, с валидацией токенов (OIDC, PKCE, проверка issuer/audience).
