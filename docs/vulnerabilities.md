# Уязвимости и меры нейтрализации

| № | Уязвимость | Риск/последствие | Меры нейтрализации |
|---|------------|------------------|--------------------|
| 1 | Слабая сегментация сети (IT/OT) | Латеральное перемещение, вывод подсистем из строя | Сегментация L3/L2, SDN/ACL, отдельные VLAN для OT, межсетевые экраны с DPI для промышленных протоколов, jump host, mTLS |
| 2 | Необновленные прошивки/ПО | Эксплойты, ботнеты, компрометация камер/контроллеров | Централизованный инвентарь, подписанные обновления, поэтапный rollout, SBOM, уязвимость-менеджмент |
| 3 | Слабая аутентификация операторов | Неавторизованное управление сценарием (крыша/эвакуация) | OIDC+MFA, аппаратные ключи FIDO2, RBAC/ABAC, принцип наименьших привилегий, журнал аудита |
| 4 | Подмена команд/датчиков | Некорректные реакции BMS, ложные эвакуации | JWS/MAC для команд, взаимная TLS-аутентификация, валидация целостности, кросс-проверка показаний (видео+датчики) |
| 5 | DDoS на публичные API/шину | Недоступность клиентских функций (e-ticket, заказы) | WAF/Rate limiting, очереди, Circuit Breakers, изоляция критичных путей (эвакуация) от публичного контура |
| 6 | Утечка персональных данных | Штрафы, потеря доверия | Шифрование в покое/транзите, токенизация, DLP, сквозное логирование доступа к данным |
| 7 | Физический доступ к шкафам/стойкам | Саботаж, подключение несанкционированных устройств | СКУД на серверные/щитовые, пломбы, тамперы, журналы открытий, видеонаблюдение |
| 8 | Некорректные интеграции с MAX/ЕПГУ | Неверная проверка возраста/ID, спуфинг | OIDC с доверенными redirect URI, PKCE, проверка audience/issuer, аудит webhook-секретов |
| 9 | Компрометация ключей/сертификатов | Потеря доверия к устройствам и API | HSM/KMS, ротация, короткоживущие сертификаты, ACME внутри контура, secret scanning |
|10 | Ошибки конфигурации BMS/сценариев | Автоматические нештатные действия | Моделирование и тестовые полигоны, 4-eyes approval, версионирование и откаты, «dry run» режим |
