# Ключевые сценарии (5 шт.) для умного стадиона

Формат: краткое описание + use case + текстовая диаграмма/алгоритм (для отрисовки).

## 1) Бесшовный вход по e-ticket с MAX и биометрией
- Ценность: ускорение входа, снижение фрода, персонализация.
- Акторы: Посетитель, MAX, Mobile App стадиона, СКУД/турникет, BMS, Диспетчер.
- Use case:
  1. Пользователь получает e-ticket в MAX (deep link) и/или в Mobile App.
  2. На подходе BLE-маяки активируют экран e-ticket/QR.
  3. Турникет сканирует QR/NFC или биометрию (если добровольно активирована).
  4. BMS сверяет валидность, возрастные ограничения (через ЕПГУ при необходимости), статус риска.
  5. Турникет открывается, камера фиксирует проход (ONVIF snapshot), событие уходит в журнал.

## 2) Динамическая навигация и анти-скопления
- Ценность: безопасность, комфорт, сокращение времени ожидания.
- Акторы: Посетитель, Mobile App, VMS/Видеоаналитика, Навигация/RTLS, BMS.
- Use case:
  1. Видеоаналитика оценивает плотность людей и очереди в реальном времени.
  2. BMS рассчитывает альтернативные маршруты и публикает события в шину.
  3. Mobile App обновляет навигацию и отправляет пуши посетителям в зоне скопления.
  4. Переключение динамических табло и голосовых объявлений.

## 3) Заказ еды к месту и управление очередью выдачи
- Ценность: рост выручки, снижение очередей.
- Акторы: Посетитель, Mobile App, Ритейл/POS, Курьер/выдача, BMS/CEP.
- Use case:
  1. Посетитель выбирает блюда в Mobile App, оплата эквайринг.
  2. POS получает заказ, готовит, передает статус в платформу.
  3. CEP оптимизирует выдачу по секторам, назначает курьера/окно.
  4. Push с ETA и местом выдачи/доставкой к креслу.

## 4) Эвакуация и тревожная ситуация
- Ценность: безопасность, соответствие нормам.
- Акторы: ОПС/СОУЭ, Диспетчер, BMS, Mobile App/MAX, СКУД/двери, Видео.
- Use case:
  1. Срабатывание пожарного извещателя или инцидент по видеоаналитике.
  2. BMS переключает сценарий "Эвакуация": СОУЭ, световые указатели, разблокировка выходов.
  3. Уведомления в MAX и Mobile App с маршрутами, табло перенастраиваются.
  4. Диспетчер наблюдает, корректирует, фиксирует отчет.

## 5) Энергоменеджмент матча/концерта и отчетность в GR
- Ценность: снижение CAPEX/OPEX, прозрачность для надзора.
- Акторы: АСКУЭ, Энергоподсистемы (HVAC/свет), BMS/Энергия, Платформа, GR.
- Use case:
  1. Перед началом мероприятия BMS выполняет предпрогрев/предохлаждение, включает профили освещения.
  2. Во время пиков — сглаживание за счет предиктивной аналитики (ML) и частотников.
  3. Автосбор показаний АСКУЭ и формирование отчетов.
  4. Передача агрегированных данных в GR и хранение в платформе.

## Доработки для ДЗ2: новые сценарии на уровне предприятия

### 6) Мониторинг и предиктивное обслуживание оборудования
- Ценность: Снижение простоев, оптимизация затрат на ремонт.
- Акторы: Технический персонал, BMS, Платформа Maintenance, Диспетчер.
- Use case:
  1. Датчики на оборудовании (вибрация, температура) передают данные в edge-шлюз.
  2. Локальная аналитика выявляет аномалии (ML-модель).
  3. BMS коррелирует с историей, предсказывает поломку.
  4. Платформа отправляет уведомление техперсоналу, планирует обслуживание.
  5. Диспетчер подтверждает, оборудование переводится в режим профилактики.

### 7) Управление логистикой и складом
- Ценность: Оптимизация запасов, снижение потерь.
- Акторы: Складской персонал, MES, Платформа Inventory, Диспетчер.
- Use case:
  1. Датчики на полках/холодильниках отслеживают уровни запасов (еда, инвентарь).
  2. MES анализирует спрос (на основе заказов еды).
  3. Платформа рассчитывает оптимальные уровни, заказывает поставки.
  4. Персонал получает задания на пополнение, RFID сканирует перемещения.
  5. Отчет в ERP для учета.

### 8) Экологический мониторинг и энергоэффективность
- Ценность: Соответствие нормам, снижение энергозатрат.
- Акторы: Экосистемы, BMS, Платформа Energy, GR.
- Use case:
  1. Датчики CO₂/PM2.5/энергии собирают данные.
  2. Edge-аналитика оптимизирует HVAC/освещение в реальном времени.
  3. BMS применяет предиктивные модели для пиковых нагрузок.
  4. Платформа формирует отчеты, корректирует сценарии.
  5. Передача в GR и городские системы.

### 9) Интеграция с городскими системами
- Ценность: Синергия с инфраструктурой города, улучшение транспорта.
- Акторы: Городские системы, BMS, Платформа Integration, Диспетчер.
- Use case:
  1. Получение данных о трафике/погоде от городских API.
  2. BMS коррелирует с парковкой/навигацией стадиона.
  3. Платформа обновляет маршруты, управляет ЭЗС.
  4. Уведомления посетителям о пробках/альтернативах.
  5. Обратная связь в городские системы.

### 10) Бизнес-аналитика и отчетность для менеджмента
- Ценность: Принятие решений на основе данных, ROI.
- Акторы: Менеджмент, Платформа Analytics, ERP.
- Use case:
  1. Сбор данных из всех подсистем (посещаемость, энергопотребление, инциденты).
  2. Аналитика рассчитывает KPI (OEE, ROI мероприятий).
  3. Платформа генерирует дэшборды и отчеты.
  4. Менеджмент принимает решения (оптимизация тарифов).
  5. Интеграция с ERP для бюджетирования.
