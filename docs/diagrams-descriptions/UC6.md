# Описание диаграммы UC6: Мониторинг и предиктивное обслуживание оборудования

## Общее описание
Диаграмма иллюстрирует сценарий предиктивного обслуживания оборудования на стадионе, эволюционировавший от простого IoT-мониторинга к полноценному IIoT-решению на уровне предприятия. Сценарий фокусируется на снижении простоев оборудования через раннее обнаружение аномалий с использованием edge-аналитики и машинного обучения, интегрированного с MES-системами.

## Переход от стадиона к уровню предприятия
Изначально сценарий был ориентирован на потребительский IoT для стадиона: базовый сбор данных от датчиков для ручного обслуживания. В версии IIoT для предприятия добавлены:
- Edge-обработка данных для реального времени и снижения задержек.
- Предиктивные модели ML для прогнозирования поломок.
- Интеграция с MES для автоматизированного планирования обслуживания.
- Цифровые двойники оборудования для моделирования износа.
- Zero Trust безопасность для доступа к критическим системам.
Это отражает переход от реактивного обслуживания к проактивному, с фокусом на надежность и оптимизацию OPEX.

## Детальное описание диаграммы
Диаграмма представляет собой потоковую диаграмму с элементами IIoT-архитектуры. Основные компоненты:

### Визуальные элементы
- **Датчики оборудования**: Представлены кругами с иконками (вибрация, температура). Расположены слева, на уровне "Устройства".
- **Edge-шлюз**: Прямоугольник с иконкой шлюза. Подключает датчики по промышленным протоколам (Profinet/Modbus).
- **Локальная аналитика**: Блок с иконкой ML-модели. Выполняет фильтрацию и первичный анализ аномалий.
- **BMS (Building Management System)**: Центральный блок, коррелирует данные с историей.
- **Платформа Maintenance**: Облачный блок с иконкой платформы. Генерирует предсказания и уведомления.
- **Технический персонал**: Иконка человека с инструментами. Получает push-уведомления.
- **Диспетчер**: Иконка диспетчера. Подтверждает обслуживание и переводит оборудование в режим профилактики.

### Потоки данных и связи
1. **Сбор данных**: Стрелки от датчиков к edge-шлюзу (MQTT/LwM2M для IoT, Profinet для промышленных).
2. **Edge-анализ**: Двунаправленная стрелка к локальной аналитике (TSN для детерминизма).
3. **Корреляция**: Стрелка от edge к BMS (OPC UA).
4. **Предсказание**: Стрелка от BMS к платформе (MQTT с QoS).
5. **Уведомление**: Push-стрелка к техперсоналу (WebSocket/OAuth2).
6. **Подтверждение**: Обратная стрелка от диспетчера к платформе (API с MFA).

### Цветовая схема и состояния
- Зеленый: Нормальное состояние.
- Желтый: Аномалия обнаружена.
- Красный: Предсказанная поломка, срочное обслуживание.
- Синий: Команды управления (EtherCAT для актуаторов).

### Ключевые особенности IIoT
- **Edge-вычисления**: Локальная обработка снижает нагрузку на облако и обеспечивает работу в оффлайн.
- **Интеграция OT/IT**: BMS как мост между операционными технологиями (датчики/PLC) и IT (платформа/ERP).
- **Безопасность**: mTLS для всех соединений, журнал аудита.
- **Масштабируемость**: Поддержка тысяч датчиков через кластеры edge-шлюзов.

Диаграмма подчеркивает синергию между физическими активами, цифровыми двойниками и бизнес-процессами, типичную для IIoT-предприятий.
